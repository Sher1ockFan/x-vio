# 夹爪 TCP 回放

在本地浏览器用已经求解的位姿回放夹爪工具中心点（TCP），播放沿用原始录制的时间间隔。

## 打开程序

在文件管理器里双击 `index.html`，或用浏览器打开它。保留同目录下的程序文件。使用本地文件回放时无需启动服务或安装依赖。

1. 选择 `960×768` 或 `1920×1536`。两组各含 6,139 帧，默认显示按 STEP 名义偏移换算的 TCP。用「轨迹 → 原始位姿」切换回录制时的相机轨迹。
2. 点击播放或暂停，或拖动时间轴跳转。可用 0.25×、0.5×、1×、2× 和 4× 倍速，1× 对应实际录制时间。时间轴的亮色区间对应有效位姿。
3. 「夹爪模型」叠加 STEP 装配模型，亮点为 TCP。点「模型特写」可跟随 TCP 查看模型细节，拖动旋转视角，滚轮缩放。坐标和比例尺以米为单位。切回原始相机或机体位姿时，视锥指示输入朝向。
4. 要播放自己的数据，先选择输入格式，再通过文件输入选择位姿文件。对轨迹文本请选择时间戳单位，并选择输入代表相机、IMU／机体还是 TCP。

位姿无效的时段保留在时间轴上。不同的连续轨迹段分开绘制，回放不会在失跟前后补出位姿。程序回放位姿和三维轨迹，可用于观察 TCP 随相机姿态变化的运动。

## STEP 名义 TCP 与实测偏移

名义 TCP 取自 `261118_手术刀夹爪ID文件.step` 的左右夹爪内侧前缘中点，装配坐标为 `[0, 82.48179, 35.53503] mm`。相机几何参考取模型内 YH6191 镜头曲面的前顶点。按相机右、下、前的轴向约定，从该参考点指向 TCP 的偏移约为 **[−0.053, −0.442, +143.802] mm**。它描述 STEP 当前装配姿态的名义预览。相机光心、图像轴和实机安装姿态应以标定结果为准。

每帧使用以下位置变换，偏移先从毫米换算为米。

```text
世界坐标系中的 TCP = 世界坐标系中的相机位置 + 相机到世界的旋转 × 相机坐标系中的 TCP 偏移
```

展开「TCP 偏移」，输入实测的 X、Y、Z 并点击「应用偏移」。如果标定结果是把 TCP 坐标转换到相机坐标的 4×4 矩阵 `T_camera_tcp`，取矩阵最后一列的前三项作为位置偏移。对于 IMU／机体位姿，使用该坐标系内量出的偏移。已经是 TCP 位姿的文件会直接播放。偏移只保留在当前页面内，两组内置录制共享偏移，外部文件各自设置。

## 夹爪模型叠加

浏览器显示从该 STEP 的完整装配导出的约 14.3 万个三角面，并沿用模型的比例和颜色。右爪两处无法直接网格化的修剪面用左爪的对称网格补齐，补齐点已与右爪原曲面对照。网格顶点以 TCP 为原点，按 CAD 里的相机装配姿态表达。回放时随相机的逐帧旋转移动，网格的 TCP 对准轨迹亮点。实测偏移会改变 TCP 位置，网格方向仍采用该 STEP 的安装约定。外部相机轨迹经「使用 STEP 名义值」确认该模型后也可叠加，机体和已是 TCP 的输入按各自位置回放。

开启模型时，选择内置数据会定位到最长有效段的首帧，便于直接查看模型。点「回到起点」可从录制的 0 秒播放。失跟或时间戳空段内收起模型，保持轨迹原有的有效性。

## 支持的输入格式

| 输入格式 | 格式选择 | 时间戳 | 每行内容 |
| --- | --- | --- | --- |
| 本项目 `poses.csv` | 自动识别 poses.csv，或 ORB 位姿 CSV（ns） | `camera_ns`，整数纳秒 | 带表头，字段见下方 |
| TUM 轨迹文本 | 八列 TXT（秒） | 秒，支持小数 | `timestamp tx ty tz qx qy qz qw` |
| ORB-SLAM3 EuRoC 样式轨迹文本 | 八列 TXT（纳秒） | 纳秒，允许导出时间戳带小数 | `timestamp tx ty tz qx qy qz qw` |

三种格式的位置字段均按米显示。四元数按 **qx、qy、qz、qw** 排列。样本须按时间戳严格递增，时间轴以文件的第一条记录为 0 秒。轨迹使用文件给出的坐标系和姿态定义。本项目 `poses.csv` 记录的是相机到世界的位姿。ORB-SLAM3 的部分惯性导出记录的是 IMU 或机体到世界的位姿，可在导出程序中确认具体含义。

### 本项目位姿 CSV

必需字段为 `camera_ns`、`valid`、`tx`、`ty`、`tz`、`qx`、`qy`、`qz` 和 `qw`。可选字段 `frame_idx`、`map_id`、`recovery_id` 用于保留原始帧号以及识别帧号缺口、地图切换和恢复边界。项目导出的其他诊断列可以保留。

`valid=1` 表示该行有有效位姿，需要提供有限的平移和非零四元数。`valid=0` 表示该帧位姿无效，平移和四元数可留空或填写 `nan`。

```csv
frame_idx,camera_ns,map_id,recovery_id,valid,tx,ty,tz,qx,qy,qz,qw
0,18562045998062,0,0,0,nan,nan,nan,nan,nan,nan,nan
1,18562062663078,0,0,1,0.03,0.01,0,0,0,0,1
```

### 八列轨迹文本

每行用空格或制表符分隔，允许空行和以 `#` 开头的注释。TUM 示例的时间戳以秒计。

```text
0.000000 0 0 0 0 0 0 1
0.016667 0.03 0.01 0 0 0 0 1
```

ORB-SLAM3 的 `CameraTrajectory.txt` 或 `KeyFrameTrajectory.txt` 可按实际导出格式选择秒或纳秒。下面两条示例采用纳秒时间戳。

```text
18562045998062.000000 0 0 0 0 0 0 1
18562062663078.000000 0.03 0.01 0 0 0 0 1
```

轨迹文本没有逐帧有效性字段，程序会按较大的时间间隔分段。若需要保留每个无效帧，以及精确标注地图或恢复边界，请使用 `poses.csv`。EuRoC 数据集的真值 `data.csv` 字段和四元数顺序与此处的八列文本不同，需先转换成上表中任一格式。
